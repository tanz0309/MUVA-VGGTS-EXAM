# MUVA 分块子集评估方案（已确认）

状态：用户于2026-11-17再次确认图示中的六项精度主指标：Visible mIoU、Dice、Boundary F、CR@50、SCR@50、全分块覆盖成功率。模型运行状态另见可运行性检查报告。

实现：INSID3、O-MaMa、VGGT-S、V²-SAM 均调用 `scripts/common.py` 的同一个 `metrics()` 和 `summarize()`，由 `scripts/run_experiment.py` 的 `evaluate()` 生成报告；训练过程中的验证也使用这个评估器。六项精度主指标已统一实现，JSON/CSV字段依次为 `visible_iou`、`dice`、`boundary_f`、`cr50`、`scr50`、`all_components_covered50`。耗时为辅助信息，VGGT-S受预测点缓存命中影响，须按第2.7节单列。

## 1. 任务与输入

目标：给定参考视角中的一个物体，在目标视角输出该物体的**可见区域二值掩码**，评价跨视角识别、可见区域分割及小分块恢复。

- 案例来源：`/root/datasets/MUVA_fragmented_dataset/pairs.csv`。
- 原始 RGB 与标注：`/root/datasets/MUVA`。
- 分块目录中的 `reference.jpg` 和 `target.jpg` 已叠加真实掩码并添加信息栏，仅供人工查看，不能作为模型原始 RGB 输入。
- 使用清单中的原图路径、标注 ID 获取原始图片及独立二值掩码。
- 统一基础输入为参考 RGB、参考物体可见掩码、目标 RGB。模型原生的提示编码可适配，但需明确记录额外输入。
- 目标 GT 只用于训练监督或评估；验证/测试推理不能用它生成提示、确定裁剪框、选择候选输出或执行后处理。
- 如果模型需要文本，另行记录文本来源；禁止直接从目标 GT 提取位置等信息。

## 2. 建议的主表指标

记每个案例的预测可见掩码为 P，完整真实可见掩码为 V。所有掩码在原始目标图坐标下评价，图片顶部渲染信息栏不参与计算。

| 指标 | 方向 | 用途 |
|---|---|---|
| Visible mIoU | 越高越好 | 主要排名指标，整体可见区域是否分得准确 |
| Visible Dice | 越高越好 | 区域重叠指标，与IoU具有较强相关性 |
| Boundary F-score | 越高越好 | 边界质量，补充区域重叠评价 |
| Component Recall@50（CR@50） | 越高越好 | 每个显著可见分块是否至少恢复一半面积 |
| Smallest-Component Recall@50（SCR@50） | 越高越好 | 最小显著可见分块是否至少恢复一半面积 |
| 全分块覆盖成功率 | 越高越好 | 同一案例的全部显著GT分块均覆盖至少50%时，该案例才算成功 |

### 2.1 Visible mIoU：逐案例宏平均

每个案例：`IoU = |P ∩ V| / |P ∪ V|`。

总体：`Visible mIoU = (1/N) × Σ IoU_i`。

这里 mIoU 指每个物体—目标视角案例的 IoU 等权平均，不是类别平均，也不是把所有像素合并后的累计 IoU。累计 IoU 可附加输出，但不能混用命名或替代主指标。

预测与 GT 均使用完整可见掩码；不要为了提高分数而删掉预测中的小区域，也不要把统计分块时的碎片阈值直接用于删除 GT 像素。

### 2.2 Visible Dice

每个案例：`Dice = 2|P ∩ V| / (|P| + |V|)`，然后逐案例取平均。

单个案例有 `Dice = 2IoU / (1 + IoU)`，但平均 Dice 不能直接由平均 IoU 换算。Dice列为本实验六项主指标之一。

### 2.3 Boundary F-score

采用 DAVIS 风格的轮廓匹配精确率、召回率及其调和平均。使用统一容差：`ceil(0.008 × sqrt(H² + W²))` 像素，H、W 为原始图像尺寸；1920×1080 图像对应 18 像素。

该容差可能容忍细小误差，因此 BF 不能单独证明没有错误连接。若增加更严格的 2 像素版本，必须另记为 `BF@2px`，不可与默认 BF 混为一列。

参考：[DAVIS 原论文，CVPR 2016](https://www.cv-foundation.org/openaccess/content_cvpr_2016/html/Perazzi_A_Benchmark_Dataset_CVPR_2016_paper.html)。本地 ObjectRelator 与 V²-SAM 的评估工具中也存在 Boundary F 实现；统一实验仍应使用同一评估器。

### 2.4 CR@50：本课题的分块诊断指标

先对 GT 可见掩码做 8 邻域连通分量分析，保留面积 `>= max(10, ceil(0.01 × |V|))` 的分块，记为 C_1 … C_K。与现有分块子集筛选规则一致。

每块的面积覆盖率：`coverage_k = |P ∩ C_k| / |C_k|`。

每案例：`CR@50 = (1/K) × Σ 1[coverage_k >= 0.5]`；总体按案例宏平均。

它衡量分块是否被覆盖，不是分块 IoU，也不要求预测恰好产生 K 个连通区域。不会用“碰到一个像素”作为成功标准。

CR@50 是本实验明确规定的诊断口径，不声称是这四篇论文原生共同采用的标准指标。可附加 CR@25、CR@75 验证结论对阈值是否敏感，不能看完测试结果再选择最有利阈值。

**限制：**大面积错误涂满也可能得到高覆盖率，必须与 IoU、像素 Precision 一起解读，不能单独排名。错误连接两个真分块的预测可能覆盖率很高；此时额外错误像素应由 IoU、Precision 等惩罚。

### 2.5 SCR@50

每案例选择 GT 面积最小的显著分块，按上述 50% 面积覆盖标准判定成功，再对案例取平均。如果最小面积并列，先对所有并列最小分块取成功率平均，再纳入总体均值，避免任意选择。

例：大块 1000 像素，小块 50 像素。若预测恰好只包含大块且无误检，则 IoU 约 95.24%，CR@50 为 50%，SCR@50 为 0。这说明仅看整体 IoU 会掩盖小块完全漏掉的问题。

### 2.6 全分块覆盖成功率

每案例：`success_i = 1[每个显著GT分块的coverage均 >= 0.5]`；总体：`(1/N) × Σ success_i`。保存字段为 `all_components_covered50`。

例如三个分块覆盖率100%、60%、20%时，该案例失败；100%、60%、50%时才成功。它与CR@50不同：CR按案例内达标分块比例计分，本项要求该案例全部分块达标。

CR@50、SCR@50和本项均沿用第2.4节相同的显著GT分块定义，不修改完整GT用于IoU、Dice或Boundary F的像素范围。

### 2.7 运行成本

同一 GPU、batch size=1、预热后计时，GPU 计时前后同步。每对计时包含该对图像必要的特征提取、匹配、提示生成、解码和必要后处理，排除一次性加载权重、读盘、保存可视化、评估 GT 的耗时。

如果模型复用参考图特征，需单独报告缓存设置；不能将某模型首次处理完整一对的耗时与另一模型只解码目标的耗时混比。VGGT-S默认在缓存缺失时在线生成首阶段点，并计入该次推理耗时（含缓存读写）；命中缓存时跳过首阶段。预热也会产生缓存。因此当前整体耗时受缓存命中情况影响，不能与其他方法完整在线图对直接作同口径比较。记录`timing`、`point_cache_usage.json`和逐例点来源，六项精度指标不受统计口径改变。除平均耗时外保存中位数、P95 和 GPU 峰值显存。显存不纳入精度排名。

## 3. 补充指标与消融

### 所有模型可共同输出

- 像素 Precision：`|P ∩ V| / |P|`，诊断背景和遮挡物误分；本子集 GT 非空，预测为空时约定为 0。
- 像素 Recall：`|P ∩ V| / |V|`，诊断漏分。
- 空预测率、推理失败数及清单。失败不得静默删除：保留分母、按空预测记分并显示失败状态；同时修复基础设施错误，不将失败结果冒充正常完整实验。
- 当前 `summary.json` 的 `by_group` 已输出 2 块 / 3 块以上、四种场景设置、遮挡率分组；遮挡区间固定为 `[0,30%)`、`[30%,60%)`、`[60%,90%)`、`[90%,100%]`。最小分块面积分组尚未实现，不属于当前自动输出。

### 仅对能明确导出点提示的阶段做机制分析

- 提示分块覆盖率：显著 GT 分块中至少落入一个有效正提示点的比例。
- 候选点到最终提示的分块覆盖损失：统计候选阶段已覆盖、压缩后失去全部正提示的分块比例。
- 正提示精确率：落在真实可见目标内的正提示占全部正提示的比例。
- 提示数量和预算。固定预算比较和自适应预算比较分开，避免把增加点数当作分配方法的独立收益。

上述提示指标不强加给没有对应显式点提示接口的模型；不可虚构提示点来填充共同主表。

### 不作为跨模型共同主指标

- Amodal IoU：评价被遮住部分的完整物体掩码，与当前可见分块恢复目标不同。只有方法实际提供对应输出且输入/监督可比时才另列实验。
- Occluded IoU：同理。不能用同一张可见预测同时冒充完整掩码预测。
- Pixel Accuracy：大量背景可使分数虚高，不能替代目标 IoU。
- 预测连通块数与 GT 块数是否相等：相同数量可能位置全错，不能单独作为分块恢复成功标准。

## 4. 数据划分及可比性

沿用现有清单中的官方 train/val/test 归属，不对配对记录重新随机切分：

| 划分 | 分块案例数 | 用途 |
|---|---:|---|
| train | 6224 | 需要训练的方法在此训练 |
| val | 2215 | 调参与选择模型、阈值 |
| test | 2008 | 最终冻结配置后的比较 |
| 合计 | 10447 | 不应合并为一个正式测试分母 |

数据准备已检查场景、视角、物体记录一致性，跨划分场景/图像交集为0；避免同一场景中的不同配对被人为随机拆到训练和测试两边。

免训练方法也在相同 val/test 案例上评价，阈值等仅用 val 调整。需训练的方法可配置 train 与 val，最终 test 只用于报告。零样本权重、MUVA 训练权重的结果分开标记，注明基础预训练来源和MUVA任务训练方式。

各模型输出还原到原始 1920×1080 目标图坐标；记录裁剪及缩放策略。二值化采用各模型固定的原生规则，或只在 val 上确定的规则，不能依据目标测试 GT 调阈值或挑选多候选掩码中的最好结果。

当前子集只包含分块案例。对其取得改进只能支持分块条件下的结论；若要主张整体性能或单块无退化，后续必须补充独立的全量/非分块评估。

如需置信区间，建议以场景为单位重采样；同一场景多物体、多视角不应被当作完全独立样本。

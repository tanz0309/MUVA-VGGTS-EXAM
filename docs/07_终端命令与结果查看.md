# 四种模型的训练、验证命令与保存位置

> 2026-11-18 起统一以本 Git 项目运行和维护，现有数据与结果通过忽略的本机链接复用，配置中的固定官方依赖路径保持兼容。详见文档 11。

以下命令用 `--output` 显式指定目录，实验名统一为 `muva_seed42_run01`，因此训练权重和验证结果的位置是确定的。脚本自动使用每个模型已有的 Conda 环境，不用先 activate；模型运算使用 GPU，种子为42。

2026-11-17恢复到RTX4090服务器，四个独立Conda环境与GPU检查已通过，验收证据见文档06。当前配置如下，学习率、训练轮数、损失及官方网络结构保持原方案。

| 方法 | 单卡前向batch | 梯度累积 | 每次更新图对数 | 轮数 |
|---|---:|---:|---:|---:|
| INSID3 | 1 | — | 免训练 | — |
| O-MaMa | 24 | 1 | 24；最后一批保留不足24对的样本 | 3 |
| VGGT-S | 8 | 1 | 8 | 12 |
| V²-SAM Fusion | 16 | 1 | 16 | 24 |
| V²-SAM Visual | 16 | 1 | 16 | 12 |

- `GPU_ID=0` 指物理0号卡，改为1可用另一张卡；同一张卡上的实验请依次运行。
- 新实验的输出目录必须不存在。重复新实验时，把相关命令中的 `run01` 一起改成 `run02`，已有结果不会覆盖。
- 已经按旧命令启动的实验仍保存在终端 `OUTPUT_DIRECTORY` 打印的时间戳目录，不会自动搬到下面的固定目录。使用已有训练结果时，给 `--checkpoint` 填入该次训练的真实 `best.pth`。
- 下面是 train 训练集和 val 验证集命令；最终 test 的用法见第6节。完整实验由用户启动。

```bash
  --output /root/repos/MUVA-VGGTS-EXAM/outputs/insid3/evaluate/val_muva_seed42_run01
```

| 内容 | 路径 |
|---|---|
| 验证结果目录 | `/root/repos/MUVA-VGGTS-EXAM/outputs/insid3/evaluate/val_muva_seed42_run01/` |
| 使用的DINOv3预训练权重 | `/root/INSID3/pretrain/dinov3_vitl16_pretrain_lvd1689m-8aa4cbdd.pth` |

用户此前已完成的一次INSID3验证在 [原运行目录](../outputs/insid3/evaluate/val_training_free_20261106T082528466306Z)，可直接查看其中的 `summary.csv`，无需为查看结果重跑。

```bash
  --output /root/repos/MUVA-VGGTS-EXAM/outputs/omama/train/muva_seed42_run01
```

```bash
GPU_ID=0 bash /root/repos/MUVA-VGGTS-EXAM/run.sh evaluate omama --split val \

  --output /root/repos/MUVA-VGGTS-EXAM/outputs/omama/evaluate/val_muva_seed42_run01
```

## 5. 验证完成后看哪些文件

下表中的位置均相对于该次验证命令的 `--output` 目录。训练期间的自动验证也在各 `val_epoch_XX/` 内生成相同文件。

| 文件／目录 | 内容 |
|---|---|
| `summary.csv` | 汇总六项主指标：Visible mIoU、Dice、Boundary F、CR@50、SCR@50、全分块覆盖成功率；另含同口径 70% 阈值补充指标 `cr70`、`scr70`、`all_components_covered70`，以及辅助指标和耗时。2026-11-19 之前生成的旧结果不含这三项，可从 `component_coverages` 或预测掩码重算 |
| `summary.json` | 同一汇总，另有分块数、场景设置、遮挡率分组 |
| `per_case.csv` | 每个图对的分数、耗时、失败状态 |
| `per_case.jsonl` | 逐例即时写入的记录，运行中即可查看 |
| `predictions/*.png` | 原始目标图尺寸的二值预测掩码 |
| `prompts/*.json` | 提示点或专家选择等审计，随方法不同 |
| `errors/*.txt` | 捕获的单例推理异常；没有异常时不生成 |
| `run_config.json` | 运行配置、环境、数据清单与权重等信息，具体字段随入口不同 |
| `status.json` | 是否完整结束 |
| VGGT-S的 `point_cache_usage.json` | 按需生成与复用计数，包含预热及训练期间验证 |

`summary.csv/json`、`per_case.csv` 在完整划分结束后生成。`failed False` 表示该例推理没有抛出异常，不代表分割准确；正常返回空掩码也可为False。普通单例异常保留分母并按空预测计分；OOM或中断会令运行不完整。最终失败数看汇总 `failures`，不能仅根据每25例打印一次的进度判断。

精度分数按0～1保存；报告百分数时统一乘100。VGGT-S耗时受点缓存命中情况影响，不能与其他模型完整无缓存图对耗时直接排名；`timing` 字段说明具体范围。

训练目录中的 `training.jsonl` 记录训练过程；`best.pth` 是最佳验证权重，`last.pth` 是最近完整epoch的权重与恢复状态。二者随训练进度生成，并非启动时就存在。训练根目录的 `summary.json` 是训练摘要；逐轮精度应查看 `val_epoch_XX/summary.csv`。

终端输出同时保存到 `/root/repos/MUVA-VGGTS-EXAM/logs/<模型>_<动作>_<时间戳>_<进程号>.log`。命令开始打印的 `OUTPUT_DIRECTORY` 是本次实际结果目录。

## 6. 最终测试、恢复训练与小规模检查

### 最终test

把相应验证命令的 `--split val` 改为 `--split test`，并将 `--output` 路径末尾的 `val_muva_seed42_run01` 改为 `test_muva_seed42_run01`。保持同一训练得到的 `best.pth`。test不用于选模型或调阈值。

### 恢复训练

仅支持从保存的完整epoch恢复，新输出目录必须尚不存在。以VGGT-S为例：

```bash
GPU_ID=0 bash /root/repos/MUVA-VGGTS-EXAM/run.sh train vggts \
  --resume /root/repos/MUVA-VGGTS-EXAM/outputs/vggts_official/train/muva_seed42_run01/last.pth \
  --output /root/repos/MUVA-VGGTS-EXAM/outputs/vggts_official/train/muva_seed42_run01_resume01
```

O-MaMa、Fusion、Visual同理替换模型名与各自路径。恢复总轮数仍为配置轮数，不是额外追加；若新运行没有超过旧最佳分数，最佳权重仍在原目录。INSID3和Anchor无需恢复训练。

### 小规模检查

以下只验证能否运行，不是正式训练或完整验证：

```bash
GPU_ID=0 bash /root/repos/MUVA-VGGTS-EXAM/run.sh smoke insid3
GPU_ID=0 bash /root/repos/MUVA-VGGTS-EXAM/run.sh smoke omama
GPU_ID=0 bash /root/repos/MUVA-VGGTS-EXAM/run.sh smoke vggts
GPU_ID=0 bash /root/repos/MUVA-VGGTS-EXAM/run.sh smoke v2sam-multi

GPU_ID=0 bash /root/repos/MUVA-VGGTS-EXAM/run.sh smoke-train omama
GPU_ID=0 bash /root/repos/MUVA-VGGTS-EXAM/run.sh smoke-train vggts
GPU_ID=0 bash /root/repos/MUVA-VGGTS-EXAM/run.sh smoke-train v2sam
GPU_ID=0 bash /root/repos/MUVA-VGGTS-EXAM/run.sh smoke-train v2sam-visual
```

4090当前配置下，V²-SAM每个microstep为16图对，累积1次完成1次优化器更新。检查生成的 `smoke_checkpoint.pth` 不能用于正式评价或恢复正式训练。

省略 `--output` 时，默认使用 `outputs/<模型>/<模式>/<时间戳运行名>/`；VGGT-S使用 `outputs/vggts_official/<模式>/<时间戳>/`。这些默认输出与本文显式指定的固定目录都合法，以实际命令为准。

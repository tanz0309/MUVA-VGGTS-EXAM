# 数据准备与划分

## 数据来源

- 案例清单：`/root/datasets/MUVA_fragmented_dataset/pairs.csv`，10447 条。
- RGB：`/root/datasets/MUVA/images/`。
- GT：`/root/datasets/MUVA/annotations/AiFi-MUVA_{train,val,test}.json` 中的 `visible_segmentation`。
- 原始图像为 1920×1080；可视化 JPG 包含信息栏和 GT 绿色叠加，只用于人工查看，不作为模型输入。

## 处理流程

1. 沿用清单的 split、物体 ID、参考/目标标注 ID，不重新随机配对或切分。
2. 检查每对的物体 ID、场景 ID 一致，参考与目标视角不同，图片路径与官方标注一致。
3. 解码所需可见 RLE，保存 0/255 的 PNG；同一 split 下相同标注 ID 只导出一次。
4. 对每个目标重新计算可见面积、8 邻域分块及最小分块阈值，与现有清单比对。
5. 生成模型共用的 `data/manifests/train.jsonl`、`val.jsonl`、`test.jsonl`。
6. 按完整原始场景路径和图像路径检查 split 之间的交集，不只比较会在不同 split 复用的数字 scene_id。

已完成计数为 train 6224、val 2215、test 2008。实际完成及检查状态记录在 `data/preparation_report.json`。

## 推理输入与监督隔离

每个清单记录拆为 `inputs` 和 `supervision`。公共读取函数只向模型的 `predict(reference, reference_mask, target)` 传入三项输入；目标 GT 在返回预测之后才用于评分。

VGGT-S 目标裁剪和正提示均从参考提示传播的 VGGT 跟踪点产生，不读取目标 GT 框。训练时可以访问 train 目标掩码作为损失监督，但仍在确定跟踪点、裁剪框后读取监督，不用 GT 挑选测试输出。

这个子集的“入选”本身来自 GT 分块统计，是条件评测集的定义，不等于允许将目标 GT 输入模型。

## 重新生成

```bash
bash /root/datasets/MUVA_experiments/run.sh prepare
```

该命令使用 `insid3-muva` 环境执行 RLE 解码和图像文件操作，不运行神经网络。若 PNG 已存在则核对内容；发现不一致会报错。不要在实验运行时修改清单或重建输入。
